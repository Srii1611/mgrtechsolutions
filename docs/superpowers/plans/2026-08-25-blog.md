# Blog System Implementation Plan (Phase 5)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn 132 finished articles into 132 statically generated pages with distinct titles, plus a searchable index and six category pages — making the site's largest content asset visible to search for the first time.

**Architecture:** The markdown lives in `content/blog/` and is read at build time by a server-only module using `node:fs`. Each post carries its own frontmatter, so a post's category can never disagree with the page it appears on. `generateStaticParams` emits one static route per post. Only the index's filter UI is a client leaf.

**Tech Stack:** Next.js 16.3 App Router, TypeScript, Tailwind v4, gray-matter, react-markdown, remark-gfm, Vitest.

**Spec:** `docs/superpowers/specs/2026-08-25-mgrtech-site-rebuild-design.md`

## Global Constraints

- **Phone `774-460-1116`** via `SITE`; `508-306-1802` nowhere.
- **No page may assert a headcount of one.**
- **`content/` is exempt from `verify:copy`** and must stay exempt. Twelve articles say "one person" as advice to the reader about *their* business — that is not a claim about MGRTECH. **Do not edit article prose. Do not widen the guard to cover `content/`.**
- **No hex values in components** — tokens only.
- **`accent-ink` is the only accent-family token legible as text on cream** (5.0:1). `accent` is for text on forest (10.4:1). Never `accent` or `accent-strong` as text on cream.
- `.on-dark` on dark sections.
- **`prefers-reduced-motion: reduce` disables transforms and transitions entirely.**
- Mobile-first; semantic HTML; every `<section>` reachable in the heading outline; WCAG AA.
- **Server Components by default**; `'use client'` only on leaves.
- Motion is Framer Motion + Lenis only.
- **Article bodies are untrusted-ish content rendered as markdown.** Do NOT enable `rehype-raw` or otherwise allow raw HTML through — react-markdown's default (HTML disabled) is what we want.

**RULING — the articles gain frontmatter; their prose does not change.**
The spec says posts are "ported unchanged" *and* that "category pages are derived from post frontmatter". The source files have no frontmatter — category lives in a separate `briefs.json`. A side-car map is exactly the drift the spec warns against, so the port injects frontmatter and leaves every word of the body untouched. `verify:copy` still exempts `content/`.

Sources:
- Articles: `C:/Clients/Site Information/app/src/content/blog/*.md` (132 files, each starts with a single `# H1`)

- [ ] **Step 1: Write the port script**

Create `scripts/port-blog.mjs`. It must:

1. Read `briefs.json` and build a `slug → category` map.
2. For each `.md` file in the source directory:
   - Derive `slug` from the filename (basename without `.md`).
   - Extract `title` from the leading `# ` H1 line.
   - Look up `category`; **if a slug has no brief, fail loudly and stop** — do not guess or default.
   - Map the category name to its slug using the table in Step 2. **Fail on an unmapped category name.**
   - Write `content/blog/<slug>.md` as frontmatter followed by the body **with the leading H1 removed** (the page renders the title as its own `<h1>`; leaving it in produces two).
3. Print a summary: files written, and a per-category count.
4. Exit non-zero on any failure.

Frontmatter shape — quote the title with double quotes and escape any inner double quotes:


### Task 2: The blog library

**Files:**
- Create: `src/lib/blog.ts`, `src/lib/blog.test.ts`

**Interfaces:**
- Consumes: `content/blog/*.md`, `CATEGORIES` from Task 1
- Produces:
  - `type BlogHeading = { depth: 2 | 3; text: string; id: string }`
  - `type Post = { slug: string; title: string; category: string; categorySlug: string; excerpt: string; readTime: number; headings: BlogHeading[]; body: string }`

This module uses `node:fs` and is **server-only**. Add `import 'server-only'` at the top after installing the package, so a client component importing it fails at build time rather than shipping the filesystem read to the browser.

- [ ] **Step 4: Implement `src/lib/blog.ts`**

Requirements:
- Read every `.md` in `content/blog/` once, at module load, and cache the result. The build calls these functions hundreds of times; re-reading 132 files each call is wasteful.
- Parse frontmatter with `gray-matter`.
- `excerpt`: the first non-empty paragraph of the body, with markdown emphasis markers stripped, capped at ~280 characters on a word boundary.
- `readTime`: `Math.max(1, Math.round(wordCount / 225))`.
- `headings`: every `##` and `###` in the body, in document order, each with `depth`, `text`, and a unique `id` from `slugifyHeading`. **Deduplicate ids within a post** by appending `-2`, `-3`, … on collision.
- `slugifyHeading`: lowercase, strip anything that is not alphanumeric/space/hyphen, collapse whitespace and hyphen runs to a single hyphen, trim leading/trailing hyphens.
- **Ignore fenced code blocks when extracting headings** — a `#` inside a fence is not a heading.
- `getAllPosts` returns posts sorted by `title`.
- Throw a clear error if a post is missing `title` or `categorySlug`, naming the file. A malformed post must fail the build loudly, never render blank.

### Task 3: Blog components

**Files:**
- Create: `src/components/blog/ArticleCard.tsx`, `ArticleBody.tsx`, `Toc.tsx`, `CtaBand.tsx`, `BlogFilter.tsx`

**Interfaces:**
- Consumes: `Post`, `BlogHeading` from `@/lib/blog`; `CATEGORIES`; `SITE`; `Reveal`
- `ArticleCard`, `ArticleBody`, `Toc`, `CtaBand` are Server Components. **`BlogFilter` is the only `'use client'` leaf.**

**`ArticleCard`** — props `{ post: Post }`. Renders as an `<article>`: category label (linking to the category page), title as an `<h3>` linking to `/blog/<slug>`, excerpt, and read time. Cream surface, `border-cream-300`, hover lift. Accent text uses `accent-ink`.

**`ArticleBody`** — props `{ markdown: string }`. Renders with `react-markdown` + `remark-gfm`. **Do not enable `rehype-raw`.** Supply a `components` map styling each element with tokens:
- `h2` → `h2-section`, `scroll-mt-24`, and an `id` from `slugifyHeading` so the TOC anchors work
- `h3` → `h3-card`, `scroll-mt-24`, with an `id`
- `p` → readable measure, `text-ink-soft`
- `ul`/`ol`/`li` → proper list markers, not stripped
- `a` → `accent-ink`, underlined, with `rel="noopener noreferrer"` and `target="_blank"` for external links only
- `blockquote`, `code`, `pre`, `table` → token-styled; `pre` and `table` must sit in their own `overflow-x-auto` container so the page body never scrolls sideways
- `strong`, `em` → weight/italic
The heading `id`s here MUST use the same `slugifyHeading` the library uses, or the TOC links break.

**`Toc`** — props `{ headings: BlogHeading[] }`. A `<nav aria-label="On this page">` listing the headings as anchor links, indenting depth 3 under depth 2. Sticky on large screens, collapsed above the article on mobile. If `headings` is empty, render nothing.

**`CtaBand`** — props `{ eyebrow?: string; heading: string; body: string }`. A dark band with the phone CTA (`SITE.phoneHref`, `SITE.phone`) and a link to `/contact`. Uses `.on-dark`. **Do not embed a form here** — the phone and a link to `/contact` are enough, and a second form on every article page is exactly the duplication we have been avoiding.

**`BlogFilter`** (client) — props `{ posts: Post[] }`. A search input (filters on title and excerpt, case-insensitive) plus category filter buttons. Renders the filtered `ArticleCard` list. Requirements:
- The input has a real `<label>` (visually hidden is fine).
- Category buttons are toggle buttons with `aria-pressed`.
- A live region announces the result count ("24 articles").
- **When the query is empty and no category is selected, show all 132.**
- An empty result set shows a clear message, not a blank area.
